# Goose Goose Duck AI Bot Project Plan

## 1. 项目目标

做一个只用于朋友私人房间的 AI 补位玩家。它的定位不是公共匹配里的“代玩”或作弊工具，而是在朋友们缺人时，用公开身份加入房间，承担一个低风险、可接管、可解释的补位角色。

第一阶段先做成 Coach：观察屏幕、记录语音、整理局内信息、给出行动和投票建议，不直接控制游戏。

第二阶段再做成半自动 Bot：在所有朋友知情同意的私人局里，由人确认后执行有限键鼠操作。

第三阶段才考虑全自动私人局补位：只做基础移动、任务、报告和投票，并保留急停、日志和人工接管。

## 2. 使用边界

- 只用于朋友私人房间。
- 所有参与者提前知道 AI 正在补位。
- AI 玩家使用明确身份，例如 `AI_Bot`，不冒充真人玩家。
- 不进入公共匹配，不刷胜率，不影响陌生玩家体验。
- 不读取游戏内存，不抓包，不注入进程，不绕过反作弊。
- 不做隐藏式自动化或规避检测。
- 自动输入必须具备急停、窗口焦点检查、未知界面暂停和完整日志。

## 3. 核心架构

```text
屏幕截图 / 音频输入
  -> 感知层：游戏阶段、UI、任务、玩家名、语音转文字
  -> 局内记忆：玩家状态、位置、发言、目击、矛盾
  -> 决策层：规则系统 + LLM 结构化推理
  -> 动作层：建议输出 / 手动确认 / 受限键鼠控制
  -> 安全层：急停、焦点检查、未知状态暂停、日志
```

## 4. 技术路线

### 屏幕感知

- 使用 Python 作为主程序。
- 使用 `mss` 或 Windows Graphics Capture 捕获游戏窗口。
- 使用 OpenCV 做模板匹配和基础图像识别。
- 使用 OCR 识别任务文字、投票界面玩家名和聊天文字。
- 第一版只识别高层状态：大厅、行动、会议、投票、死亡/幽灵、未知。

### 语音理解

- 使用 `faster-whisper` 或同类 STT 把朋友局会议转成文字。
- 记录每段发言的时间戳。
- 如果能区分说话人，就记录说话人；如果不能，先只记录会议文本。
- 低置信度语音内容不作为强事实，只作为待确认信息。

### 局内记忆

- 使用 JSONL 或 SQLite 保存每局日志。
- 记录玩家是否存活、最后出现位置、发言声明、投票行为和可疑点。
- 把信息分成“事实”“推测”“未确认”三类。
- 会议期间根据历史记录检测简单矛盾。

### 决策层

- 行动阶段先用规则系统：做任务、避开高风险、看到尸体就报告。
- 会议阶段使用 LLM 生成结构化建议。
- 所有建议都要包含理由和置信度。
- 信息不足时默认建议提问或跳票。

示例输出：

```json
{
  "action": "vote",
  "target": "Bob",
  "confidence": 0.64,
  "say": "我之前看到 Bob 在厨房附近，他现在说的位置对不上。",
  "reason": "位置声明和目击记录矛盾"
}
```

### 动作层

- 第一版只显示建议，不自动操作。
- 第二版加入“确认后执行”按钮。
- 第三版才允许私人局自动键鼠输入。
- 控制方式可以用 `pyautogui` 或 `pynput`。
- 每次输入前检查游戏窗口是否处于焦点。
- 出现未知 UI、卡住、识别置信度低时自动暂停。

## 5. 开发阶段

### Phase 1: Coach Prototype

目标：AI 只观察和建议，不控制游戏。

验收标准：

- 能捕获游戏窗口。
- 能识别会议和投票界面。
- 能记录语音转文字。
- 能保存一局时间线。
- 能给出会议建议：提问、跳票、投票目标或信息不足。

### Phase 2: Game Memory

目标：维护一局内的事实、声明和怀疑度。

验收标准：

- 能追踪玩家存活状态。
- 能记录玩家目击和地点声明。
- 能发现简单矛盾。
- 能在会议结束后输出简短复盘。

### Phase 3: Private-Room Movement

目标：在朋友私人局中进行受限移动。

验收标准：

- 有第一张地图的手工节点图。
- 能移动到指定房间或任务点。
- 能检测卡住并停止或恢复。
- 所有操作都可以被人工立即接管。

### Phase 4: Basic Goose Gameplay

目标：先支持鹅阵营的低风险补位行为。

验收标准：

- 能做简单任务。
- 能报告明显尸体。
- 能参与会议和投票。
- 不会在不确定时乱操作。

### Phase 5: Friend-Room Automation

目标：朋友缺人时可以稳定补位。

验收标准：

- 每局前有同意确认。
- 每个 AI 动作都有日志和理由。
- 出错时能立即停下。
- 多轮私人测试后能稳定完成基础补位。

## 6. MVP 范围

第一版只做 Coach，不做自动控制。

MVP 功能：

- 捕获 Goose Goose Duck 窗口截图。
- 判断当前是否为会议或投票阶段。
- 接入语音转文字。
- 保存会议时间线。
- 输出结构化会议建议。
- 在屏幕上显示当前识别结果和 AI 建议。

暂时不做：

- 自动移动。
- 自动投票。
- 自动语音发言。
- 鸭阵营复杂策略。
- 公共匹配使用。

## 7. 风险与处理

- 识别错误：未知界面默认暂停，不盲目输入。
- 语音误识别：低置信度内容只作为待确认信息。
- 朋友体验：AI 身份公开，优先补位和娱乐，不追求强度。
- 账号风险：不绕反作弊，不做进程级操作。
- 复杂任务：第一版只支持观察和建议，复杂操作之后再拆。

## 8. 下一步

下一步直接开始 Phase 1 Coach 原型：

1. 搭建 Python 项目结构。
2. 实现游戏窗口截图。
3. 做一个简单状态识别器。
4. 接入语音转文字。
5. 保存时间线。
6. 让 AI 根据时间线输出会议建议。
